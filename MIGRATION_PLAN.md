# План перехода на NetBox-first

Этот файл — рабочий чек-лист миграции.

**NetBox-first** означает: NetBox является главным источником данных о
провайдерах, каналах и подключениях. Этот проект читает эти данные и
настраивает мониторинг. Получение текущих показателей с оборудования
передаётся в другой проект и не должно быть обязательной частью этого
запуска.

## Новые решения для обсуждения

Эти пункты зафиксированы как направление работ, но ещё не отмечены
выполненными:

- [x] Убрать опрос оборудования и зависимость от `dry-ssh.json` из рабочего
      запуска. Другой проект будет получать текущие показатели устройств.
- [x] Сделать единственным источником области мониторинга цепочку
      `Provider → Circuit → Termination → Cable → Interface → Device`.
- [x] Перестать использовать текст `Uplink:` в описании интерфейса для
      выбора, классификации или поиска канала. Описание интерфейса оставить
      только справочными данными.
- [x] Заменить требование тега `uplinks` и поля
      `uplinks_circuit_lifecycle` на правило: учитывается только Circuit с
      типом `Uplink` и встроенным статусом `Active`, остальные типы
      игнорируются.
- [x] Удалить `uplinks_circuit_lifecycle` из рабочего кода, тестов и
      документации.
- [x] После проверки использования удалить оставшееся поле
      `uplinks_circuit_lifecycle` из рабочего NetBox.

Предварительное целевое правило:

```text
Circuit Type = Uplink
AND Circuit Status = Active
AND каждый участок найденного кабельного пути имеет is_active = true
AND путь не разветвлён (is_split = false)
AND полная цепочка до интерфейса на Device с тегом border
```

В NetBox встроенный статус канала уже описывает состояние `Active`,
`Offline`, `Decommissioned` и другие состояния. Отдельное состояние `review`
не вводим: для области мониторинга используются только Circuit со статусом
`Active` и типом `Uplink`.

## Целевая цепочка

```text
Provider
  -> Circuit
  -> Circuit Termination A
  -> Cable
  -> Interface
  -> Device с тегом border
  -> Zabbix
```

В мониторинг попадает только полная цепочка до устройства с тегом `border`.
Текущие показатели устройства получает другой проект; этот проект не должен
использовать SSH-файл как источник области мониторинга.

### Piter-IX: договор № 72313

Договор подтверждает одну общую услугу с общей гарантированной полосой
20 Gbit/s. В NetBox физически заведены два Circuit, но договор не делит
гарантированную полосу между ними.

Поэтому в NetBox используется общая модель лимита:

- `Piter-IX-1`: `billing_model=FlatAggCap`, `commit_rate` не заполняется;
- `Piter-IX-2`: `billing_model=FlatAggCap`, `commit_rate` не заполняется;
- Provider `Piter-IX`: `aggregate_limit_gbps=20`.

Двадцать гигабит — общий лимит Provider, а не два отдельных лимита по
10 Gbit/s на физических линках.
