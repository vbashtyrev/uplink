# План перехода на NetBox-first

Этот файл — рабочий чек-лист миграции.

**NetBox-first** означает: NetBox является главным источником данных о
провайдерах, контурах и подключениях. Скрипт читает эти данные, получает
статистику с оборудования и настраивает мониторинг.

## Главные правила

- [x] Скрипт не создаёт Provider.
- [x] Скрипт не создаёт Circuit.
- [x] Скрипт не создаёт Circuit Termination.
- [x] Скрипт не создаёт Cable.
- [x] Скрипт не удаляет Provider, Circuit, Termination или Cable.
- [x] Скрипт не заменяет существующий кабель другим.
- [ ] Старый код автоматического создания сначала отключается, а затем удаляется
      после успешной миграции.
- [ ] Старые данные NetBox сохраняются.

Отмеченные пункты относятся к обычному запуску. Создание, изменение и замена
объектов остались только в явном режиме `--auto`, который по решению не
удаляется в этом слиянии, а будет удалён отдельно.

## Целевая цепочка

```text
Provider
  -> Circuit
  -> Circuit Termination A
  -> Cable
  -> Interface
  -> Device с тегом border
  -> SSH-опрос
  -> обновление разрешённых полей интерфейса
  -> Zabbix
```

В мониторинг попадает только полная цепочка до устройства с тегом `border`.

### Piter-IX: договор № 72313

Договор подтверждает одну общую услугу:

- гарантированная полоса: 20 Gbit/s;

В NetBox физически заведены два Circuit по 100 Gbit/s. Принято техническое
распределение общей гарантированной полосы для мониторинга:

- `Piter-IX-2`: `commit_rate=10 Gbit/s`,

- Provider `Piter-IX`: `aggregate_limit_gbps=20`.

Десять гигабит на каждый Circuit — техническое распределение для NetBox и
Zabbix, а не утверждение, что договор отдельно гарантирует 10 Gbit/s на
каждом физическом линке.

## Решение по плагинам

На первом этапе плагины не устанавливаем.

Стандартных объектов NetBox и дополнительных полей достаточно для текущей
задачи. `netbox-contract` можно рассмотреть отдельно, если потребуется
полноценный учёт договоров, счетов и стоимости. Это не должно блокировать
переход на ручное создание подключений.
