# Заполнение DCI-канала в NetBox

## Назначение

Эта инструкция предназначена для оператора, который заполняет канал связи
между двумя площадками в NetBox.

После заполнения канал типа `dci` попадает в отдельный дашборд Zabbix `DCI`.
Полный запуск uplinks не используется и этот канал не изменяет.

Площадки канала заполняются в одном регионе NetBox. Страница дашборда
называется именем этого региона. Если регионы сторон различаются, страница
берётся по стороне A, иначе по стороне Z. Если имени региона нет, страница
называется `Без региона`. Сторона A и сторона Z одного канала рисуются рядом
на одной строке.

## 1. Создайте или откройте Provider

Укажите провайдера, которому принадлежит канал.

## 2. Создайте Circuit

Заполните поля:

- **Provider** — выбранный провайдер;
- **Circuit ID** — уникальный идентификатор канала;
- **Circuit Type** — тип с именем или slug `dci`;
- **Status** — `Active`.

Сохраните Circuit.

## 3. Заполните терминации Circuit

У канала должны быть две терминации:

- одна со стороной **A**;
- одна со стороной **Z**.

Для каждой терминации укажите кабель, который продолжает путь до интерфейса
устройства на соответствующей площадке.

Сохраните обе терминации.

## 4. Проверьте кабельный путь стороны A

Откройте кабель, указанный в терминации **A**.

Путь должен доходить до интерфейса устройства через кабели и проходные порты
NetBox, если они используются. Кабель должен быть связан с терминацией
Circuit, а не только соединять два интерфейса устройств.

## 5. Проверьте кабельный путь стороны Z

Повторите проверку для терминации **Z**.

Обе стороны — A и Z — должны после полного кабельного пути завершаться на
интерфейсах устройств. Путь может проходить через OFD (оптический
кросс/распределительную панель) и её проходные порты NetBox.

## 6. Подготовьте интерфейсы устройств

На конечном интерфейсе каждой стороны проверьте:

- интерфейс включён;
- имя интерфейса заполнено;
- на интерфейсе установлен тег `dci`;
- тег `dci` установлен на обоих концах канала.

Тег `dci` устанавливается именно на объект **Interface**, а не только на
Device и не на Circuit.

## 7. Сохраните изменения NetBox

После сохранения проверьте, что в Circuit остались:

- Provider;
- Circuit ID;
- тип `dci`;
- статус `Active`;
- терминация A с кабелем;
- терминация Z с кабелем.

## 8. Выполните проверку без записи в Zabbix

На машине с проектом выполните:

```bash
python zabbix_dci_dashboard.py --dry-run
```

Команда читает NetBox и Zabbix, но не создаёт и не обновляет дашборд.
Она не изменяет ни NetBox, ни Zabbix.

В выводе канал должен иметь статус `ПОЛНАЯ` и содержать оба конца:

```text
ПОЛНАЯ cid=<Circuit ID> provider=<Provider> A=<устройство>:<интерфейс> Z=<устройство>:<интерфейс>
```

## 9. Запишите дашборд DCI

После успешной проверки выполните обычный запуск:

```bash
python zabbix_dci_dashboard.py
```

Команда покажет найденные каналы и запросит подтверждение:

```text
Записать дашборд? [да/нет]
```

Для создания или обновления только дашборда `DCI` введите ответ, который после
удаления пробелов по краям должен точно совпадать с `да`:

```text
да
```

Без этого точного подтверждения ни NetBox, ни Zabbix не изменяются.
